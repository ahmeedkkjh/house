# نظام إدارة مطعم — نسخة البداية المجانية

واجهة عربية RTL لتسجيل الأصناف والطلبات والفواتير والمصروفات والمشتريات، مع تقارير وطباعة فاتورة. **البيانات التشغيلية تحفظ في Supabase PostgreSQL، وليس في localStorage أو ذاكرة المتصفح.** المشروع لا يحتوي على بيانات دخول أو مفاتيح سرية جاهزة.

## قبل الاستخدام
- تحتاج حساب GitHub، وحساب Supabase مجاني.
- لا تحتاج شراء دومين؛ استخدم رابط النشر المجاني الذي توفره خدمة الاستضافة.
- لا تضع `service_role` key داخل ملفات الموقع. `anon/public key` فقط هو الذي يوضع في `config.js`، مع سياسات RLS المرفقة.
- الخطة المجانية ليست ضمانًا دائمًا: لها حدود استخدام، وقد يتوقف مشروع Supabase قليل النشاط مؤقتًا. احتفظ بنسخة SQL احتياطية دورية.

## 1) إنشاء قاعدة البيانات
1. افتح https://supabase.com وأنشئ مشروعًا جديدًا واختر Free.
2. من لوحة المشروع افتح **SQL Editor → New query**.
3. انسخ محتويات `supabase.sql` كاملة والصقها ثم اضغط **Run**.
4. من **Project Settings → API** (أو قسم Connect حسب شكل لوحة التحكم) انسخ **Project URL** و **anon/public key**.
5. افتح `config.js` وعدّل القيم:
   - `SUPABASE_URL`: رابط المشروع.
   - `SUPABASE_ANON_KEY`: مفتاح anon/public.
   - `RESTAURANT_NAME`: اسم المطعم الظاهر على الفاتورة.

## 2) إنشاء مستخدم آمن
1. في Supabase افتح **Authentication → Users → Add user** وأنشئ حساب المالك بالبريد وكلمة مرور قوية.
2. بعد إنشاء حساب المالك، افتح إعدادات Authentication وأوقف **السماح بالتسجيل العام (Allow new users to sign up)** إن كان مفعّلًا. أضف الموظفين يدويًا من لوحة التحكم فقط عند الحاجة.
3. لا تشارك كلمة مرور المالك مع الموظفين. جميع الحسابات المسجلة في هذا المشروع تشترك في بيانات المطعم، لذلك أوقف التسجيل العام ولا تضف إلا أشخاصًا موثوقين.

## 3) تجربة الموقع محليًا
افتح المجلد باستخدام VS Code ثم شغّل `index.html` باستخدام إضافة Live Server، أو ارفع الملفات إلى استضافة ثابتة تدعم HTTPS. لا تعتمد على فتح الملف مباشرة `file://` إذا واجه المتصفح مشكلة في الاتصال.

## 4) النشر المجاني وربط GitHub
لأن هذا مشروع إدارة معاملات، **لا تستخدم GitHub Pages لاستضافة نظام المطعم التجاري**؛ توضح وثائق GitHub أن Pages غير مخصص لاستضافة الأعمال التجارية أو خدمات SaaS. استخدم GitHub لحفظ الكود، واربط المستودع بخدمة استضافة ثابتة تسمح بهذا الاستخدام مثل Cloudflare Pages:
1. أنشئ مستودعًا جديدًا في https://github.com/new وارفع ملفات هذا المجلد.
2. أنشئ حسابًا مجانيًا في https://pages.cloudflare.com/ ثم اختر إنشاء Pages project وربطه بمستودع GitHub.
3. لأنه موقع ثابت عادي، اترك أمر البناء فارغًا إن طُلب منك ذلك، وحدد مجلد الجذر للمشروع، ثم انشره.
4. افتح رابط HTTPS الناتج، وسجّل الدخول بحساب Supabase الذي أنشأته.

## الوظائف الموجودة
- لوحة ملخص: المبيعات، المصروفات، المشتريات، وصافي حركة النقدية.
- إضافة أصناف مع سعر البيع والتكلفة، وإيقاف/تفعيل الصنف.
- إنشاء فاتورة مع عدة أصناف وكميات وخصم وطريقة دفع.
- حفظ الفاتورة وتفاصيلها في قاعدة البيانات، ثم فتح نافذة الطباعة.
- تسجيل المصروفات والمشتريات.
- تقرير حسب فترة زمنية.

## تنبيهات محاسبية وتشغيلية
- «صافي حركة النقدية» = إجمالي المبيعات − المصروفات − المشتريات. هذا ليس بالضرورة صافي الربح المحاسبي؛ يلزم احتساب تكلفة المكونات والمخزون والمرتجعات والضرائب للوصول لربح دقيق.
- هذه نسخة أولى: لا تحتوي بعد على خصائص تعديل/إلغاء الفاتورة، المرتجعات، إدارة مخزون بالكميات، أو صلاحيات مختلفة للمدير والكاشير.
- اختبر النظام ببيانات تجريبية أولًا، وراجع إعدادات النسخ الاحتياطي قبل الاعتماد عليه في العمل اليومي.
- طباعة الفاتورة تعتمد على نافذة الطباعة في المتصفح؛ قد تحتاج السماح بالنوافذ المنبثقة.

## الملفات
- `index.html`: واجهة النظام.
- `style.css`: التصميم المتجاوب.
- `app.js`: منطق الواجهة والاتصال بقاعدة البيانات.
- `config.js`: إعدادات الربط (عدّلها قبل النشر).
- `supabase.sql`: الجداول والصلاحيات ودالة إنشاء الفاتورة.
